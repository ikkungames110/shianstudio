# 顔画像生成記録 ver3.1

男女各40人、合計80人を制作し、診断用画像と対応する特徴量データを更新した。[全80人の画像一覧](顔画像一覧_ver3.html)で性別を切り替えて確認できる。

## 制作条件

承認済みの男性試作10枚を採用し、男性の残り30人と女性40人を内蔵imagegenで一人ずつ生成した。架空の成人日本人27歳、整った容姿、正面・閉口・灰色の服と背景・自然なスタジオ写真を共通条件とする。

口幅と唇の厚さは小ぶり〜中間の3段階（0.15 / 0.325 / 0.5）。厚い唇、大きい口、膨らませた口元を対象外とした。下ろし前髪は眉にかかり、毛先が眉下付近に届く自然な長さとし、オン眉・お椀状の髪型を避けた。

輪郭8種類と、目・鼻・眉・口元の組み合わせは[設計書](設計書_ver3.md)の計画を維持した。丸顔が体格の違いへ寄った男性001・017・020・022を再生成し、丸顔の指定には首・肩の体格をそろえる補足を追加した。女性の丸顔もこの補足を使用。数値とタグの配分は変更していない。追加指示は該当レコードの `generation_refinement`、生成前の文章は `plan_prompt`、最終指示は `prompt` に記録した。

全画像は1200×1600 PNG。各レコードに26形態目標・10互換タグ・髪型・最終プロンプト・生成元・画像SHA-256・目視記録を保持する。承認済み試作10枚の画像と履歴は `assets/previews/v3/male/` と `data/previews/male_faces_v3.js` にも残す。

`data/plans/` は生成前に確定した設計資料として保持したため、計画時点の `image=null` と `review_status=planned` が残る。実在画像のパスと生成後の状態の正本は上記の本番JSデータ。診断中の選択カードは引き続き画像のみを表示する。

## 目視確認と数値の扱い

本番80件は `review_status=visual_checked`。口元・髪型・正面構図・輪郭と目の見え方を確認した。一部の目の細さや傾き、唇の薄さは目標より穏やかに出ており、認められた差を `visual_review.notes` に記録した。前髪で一部が隠れる眉は `unverified_features` に記録する。

形態値とタグは生成目標に由来し、画像から実測した値ではない。`shape_feature_source=generation_target` と `shape_calibrated=false` を保持している。細かい形態の採点を実測値として扱うには、画像に基づく校正が別途必要。

## 正規化と検証

既存の [normalize_face_asset.py](../scripts/normalize_face_asset.py) を使用。画像全体に近い顔検出枠を除外し、顔を過小表示する誤検出を修正した。切り出し範囲がわずかに画像外へ出る場合は、縦横それぞれ5%以内の窓移動で吸収し、背景の複製を避ける。移動量は新規画像の `generation.crop_shift_source_pixels` に保存する。

正規化処理は、誤検出が起きた画像、切り出し位置の補正が必要な画像、通常画像、顔なし画像で確認した。

全80件について、IDの一意性、画像とレコードの一対一対応、1200×1600、SHA-256一致、26形態値の設計一致、10タグの再計算一致、口元上限、目視状態を検証した。画像の完全重複と余白補完は0件。承認済み試作10枚は本番画像とバイト一致。切り出し位置の補正は男性001と女性028の2件。

一覧HTMLのリンクとデータ読込先、診断カードが画像だけを表示する既存実装を静的に確認した。実ブラウザでの表示確認は未実施。
